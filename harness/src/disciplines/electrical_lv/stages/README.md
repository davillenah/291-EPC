# `stages`

Status: **in development**

The 12 stages of PRD section 12 as stage objects in fixed order (`table.py` holds the table copied from the PRD; a test compares both). The discipline calculates and draws nothing: a stage builds the engine input from the `PipelineContext`, calls the engine's public functions and copies the engine output into `StageResult.outputs` (pure selection of keys, no rounding, no unit change, no default for a missing datum: missing data gives `blocked` with a finding).

`engine_calls.py` is the adapter: it builds the board form of the backend (`board_design` keys) from the profile, the loads and the optional `context.engine_inputs` (mapping tables in `mappings.py`, Python constants), runs `groups_in`, `board_design.calculate` (which calls `aea_pipeline.calculate`) and `board_memo.build` ONCE per run and caches the raw result in `context.engine_cache`. Stage 4 triggers it; the other stages read their slice. The result is the same as the board calculation chain of the backend (`tests/unit/test_pipeline_wiring.py` compares them).

With a `ProjectStore` in `PipelineContext.store`, `pipeline.run()` also records every stage in the project folder (`recorder.py`); the stages themselves never write, except stage 10 through the drawing engine, under `work_dir` (with a store, `runs/<run id>/`). Without a store nothing is written.

Running the wired stages needs the engine packages on `PYTHONPATH` (the gate's `harness-tests` environment sets them); the unwired stages and stage 1 needs only `harness/src`. A stage that cannot run returns `not_available` with an explicit message and no outputs; a missing input never produces a value.
