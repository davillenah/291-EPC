# `schemas`

Status: **implemented**

JSON schemas shared by the engines, the backend and the build tools (norm register, rules, plugin manifest, WBS, schedule, backlog, manufacturer catalog) and the two data files that describe deliverables (`document-catalog.json`, `deliverable-policy.json`). Moved here from `shared/schemas` (MIG-22). `intake_answers`, `load_list` and `requirements` schemas serve the `electrical_lv` intake (MIG-30a). `project_profile.schema.json` and `master_project_state.schema.json` (MIG-31) validate the project SSOT files `project_profile.json` and `master_project_state.json` (a `template` file may hold nulls; once the status is not `template` the mandatory data cannot be null); the pipeline validates both before writing them (`electrical_lv/store.py`). `epc-progress.txt` is plain text, one line per stage: `<ISO timestamp> | run <id> | stage <n> <slug> | <status> | <message>`. `deliverable_manifest.schema.json` (MIG-32) is the manifest of one transmittal (PRD section 13: inputs, engines, normative profile with the review status of each norm record, the hash of every issued file, findings, `review_status`, `signed`, `supersedes` / `superseded_by`, plus `superseded_signature`); it carries the D21 rule (`approved_for_construction` only when every listed norm record is `verified`), embeds the finding shape (copied from `docs/harness/seeds/finding.schema.json`, which stays the source) and is written by stage 16 through the project store. A standalone finding schema is still planned. `roster.schema.json` (MIG-35b) validates `harness/.claude/roster.json`.
